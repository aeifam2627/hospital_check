# ส่งออก Excel

หน้า `/reports` เริ่มต้นที่ **แบบต้นฉบับ** ตามที่เจ้าหน้าที่เลือก

- แบบต้นฉบับ: แยกชีต `YYYY-MM ประเภท` คัดลอกสีรายแถว/รายช่อง ฟอนต์ เส้นตาราง ความกว้างคอลัมน์และความสูงแถวจากต้นฉบับของเดือนนั้น หัววัน merge 3 ช่อง ด/ช/บ ตามไฟล์เดิม เดือนสิงหาคมที่เคยตรวจรายวันยังคงช่องรายวัน
- รายละเอียดทั้งหมด: หนึ่งค่าต่อแถว ใช้สีของแถวรายการต้นฉบับ มีชีตรวมและเมื่อมีหลายเดือนจะเพิ่มชีต `YYYY-MM` สำหรับแต่ละเดือน
- ตารางวันที่แบบย่อ: แยกเวรและชนิดย่อยคนละแถว วันที่เป็นคอลัมน์ เมื่อมีหลายเดือนจะแยกชีต
- ช่วง **ทั้งหมด** อ่านทุกเดือนที่มีผลบันทึกจาก Supabase เลือกประเภทเฉพาะได้ วัน/เดือน/ปียังใช้งานได้

แบบต้นฉบับรวม NG / ICD ตามลำดับเบอร์ในแถวเก่าเฉพาะการนำเสนอ เช่น No.14/No.16 เป็น `0/4` เก็บเป็นข้อความ Excel ไม่ตีความเป็นวันที่ บนแอปยังคงเป็นคนละรายการ และชีต `รายละเอียดทั้งหมด` เก็บแยกทุกเบอร์เสมอ
รายการที่เพิ่มในระบบและไม่มีในไฟล์เดิมต่อท้ายตารางก่อนแถวผู้ตรวจ ไม่มีการทิ้งข้อมูลเพราะจับคู่ชื่อไม่พบ
ช่องว่างไม่ใช่ศูนย์ ค่าต่างมาตรฐานใช้ตัวเลขสีแดงหนาโดยคงสีพื้นเดิมไว้
ช่องจำนวนมาตรฐานใช้ snapshot ของบันทึกในเดือนนั้น; หากมีการเปลี่ยนระหว่างเดือน ดูมาตรฐานของแต่ละวันในหมายเหตุเซลล์และชีตรายละเอียด
วันที่เป็น Excel Date เวลาบันทึกในชีตรายละเอียดเป็นเวลาไทย ไม่มีเวลาบันทึกจากต้นฉบับจะปล่อยว่าง
ชีตแสดงเฉพาะเดือน/ประเภทที่มีข้อมูล หากไม่มีผลตรวจจะมีเพียงสรุปและรายละเอียดว่าง

แหล่งรูปแบบ: `server/templates/inspection-layouts.json` สร้างด้วย `node scripts/extract-export-templates.mjs` จากไฟล์ดิบใน `private/legacy-excel` โดยอ่านเฉพาะช่วง inventory ที่อนุญาต ไม่คัดลอกผลตรวจ ชื่อผู้ตรวจ โน้ตคนไข้ หรือ metadata เก่าเข้า template
เดือนใหม่ที่ไม่มีต้นฉบับใช้รูปแบบเดือนล่าสุดและปรับจำนวนวันอัตโนมัติ รองรับกุมภาพันธ์ปีอธิกสุรทิน
ระบบอ่านข้อมูลทีละ 1,000 แถว มีเพดาน 50,000 แถวต่อครั้ง หากเกินให้แบ่งช่วงรายงานเพื่อจำกัดหน่วยความจำ server

ตรวจไฟล์ดาวน์โหลดจริง: `node scripts/verify-export.mjs` ขณะเปิด dev server
